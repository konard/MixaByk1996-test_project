# Архитектурные и технические решения

## Почему Laravel 11

Laravel 11 — актуальная LTS-версия фреймворка с упрощённой структурой проекта, встроенной поддержкой Sanctum для API, и активной поддержкой сообщества.

## Библиотеки

### spatie/laravel-permission
Выбрана для управления ролями (`manager`, `admin`), так как это стандартное решение для Laravel с отличной документацией и широким использованием в сообществе. Позволяет гибко настраивать роли и разрешения через middleware и проверки в коде.

### spatie/laravel-medialibrary
Используется для привязки файлов к заявкам. Обеспечивает единообразный интерфейс для работы с файлами, автоматическое управление хранилищем, и удобный API для загрузки и получения файлов. Файлы хранятся в коллекции `attachments` модели Ticket.

### laravel/breeze
Минималистичный пакет аутентификации. Предоставляет готовые формы входа/регистрации на Blade без лишней сложности. Идеально подходит для проекта, где основной упор на бизнес-логику, а не на кастомную аутентификацию.

## Архитектурные решения

### Eloquent Scopes
Для расчёта статистики и фильтрации используются Eloquent scopes (`createdToday`, `createdThisWeek`, `createdThisMonth`, `byStatus`, `byEmail`, `byPhone`, `byDateRange`). Это позволяет:
- Переиспользовать логику фильтрации в разных контроллерах
- Соблюдать принципы DRY и SRP
- Легко комбинировать фильтры через цепочку вызовов

### API Resources
Все API-ответы оформлены через Laravel API Resources (`TicketResource`, `CustomerResource`, `MediaResource`, `TicketStatisticsResource`). Это обеспечивает:
- Единообразный формат ответов
- Контроль над тем, какие данные отдаются клиенту
- Лёгкую расширяемость при добавлении новых полей

### Form Requests
Валидация вынесена в отдельные Form Request классы (`StoreTicketRequest`, `UpdateTicketStatusRequest`). Это соответствует принципу SRP — контроллер не занимается валидацией.

### Ограничение на отправку (Rate Limiting)
Реализовано на уровне бизнес-логики в контроллере: проверяется, есть ли у клиента (по телефону или email) заявка, созданная менее 24 часов назад. Возвращается HTTP 429 с понятным сообщением.

### Виджет как отдельная страница
Виджет реализован как самостоятельная Blade-страница (`/widget`) без зависимости от layout админ-панели. Это позволяет:
- Встраивать виджет через `<iframe>` на любой сайт
- Минимизировать загружаемые ресурсы
- Использовать AJAX для отправки формы без перезагрузки страницы

### Клиент (Customer) как отдельная сущность
Customer выделен в отдельную модель с уникальными phone и email. При повторной заявке с тем же номером телефона данные клиента обновляются, а новая заявка привязывается к существующему клиенту. Это предотвращает дублирование и позволяет отслеживать историю обращений.

### Docker
Конфигурация Docker включает три сервиса:
- **app** — PHP-FPM 8.4 с необходимыми расширениями
- **nginx** — Веб-сервер с проксированием на PHP-FPM
- **db** — MySQL 8.0 с healthcheck для корректного запуска

## Соответствие принципам

- **SOLID**: Каждый класс имеет одну ответственность (SRP), контроллеры зависят от абстракций Form Request (DIP)
- **MVC**: Чёткое разделение на модели, контроллеры и представления (Blade)
- **KISS**: Минимальная сложность — без лишних абстракций, сервисных слоёв там, где они не нужны
- **DRY**: Логика фильтрации вынесена в Eloquent scopes, валидация — в Form Requests
- **PSR-12**: Код соответствует стандартам кодирования PHP
